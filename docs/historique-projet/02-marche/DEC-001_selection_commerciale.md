# DEC-001 — Sélection commerciale avant réalisation

Date : 2026-11-12  
Statut : appliquée pour le programme 100 Days / 100 Games  
Périmètre : tous les projets, à réviser après chaque test réel.

## Contexte

Le programme vise 100 jeux mobiles autonomes mais n'a pas encore mesuré l'intérêt réel pour un premier concept. Le marché est concurrentiel et les règles Apple/Google interdisent les applications répétitives. Les premiers essais de conception technique sont intervenus avant l'étude commerciale.

## Décisions

1. **G0 — Recherche commerciale obligatoire** pour chaque nouveau jeu : segment, concurrents, valeur originale, modèle de revenu, coûts et risques.
2. **G1 — Test de désirabilité** avant de financer un prototype approfondi. Des visuels conceptuels doivent être clairement indiqués comme tels ; pas de fausse capture de gameplay.
3. **G2 — Prototype** seulement si la mécanique centrale est comprise et appréciée par des joueurs externes. Le prototype se concentre sur le cœur de jeu, sans achats ni SDK publicitaire.
4. Les scores de recherche sont des **jugements pondérés**, pas des probabilités de succès ni des résultats d'étude primaire.
5. Les doublons détectés sont éliminatoires. Exemples observés : *Parcel Flow: Route Puzzle* ; *Arrows Cascade – Puzzle Escape* ; plusieurs *Block Bloom* et un jeu intitulé *Foldspace*.
6. **Pas d'automatisation multiagents systématique** avant d'avoir prouvé un gain mesurable par rapport à un agent principal et des skills adaptés.
7. Le premier produit reste **non sélectionné**. Deux hypothèses sont à tester : SWITCHWORKS (priorité 1) et FOLDSPACE (priorité 2, nom non disponible présumé).

## Éviter une généralisation abusive

Ces règles pourront être ajustées après les observations réelles. Elles ne préjugent pas de la réussite économique des jeux. Un résultat positif chez un concurrent ne démontre pas la demande pour un clone.
